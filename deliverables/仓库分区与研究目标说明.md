# 水下六足机器人项目仓库分区与研究目标说明

## 文档目的

本文档面向项目导师、科研人员和跨学院协作成员，用于快速了解水下六足机器人项目的研究目标、仓库分区、接口约定、任务边界与阶段验收方式。

当前仓库已经完成项目协作框架、接口规范、配置模板和任务管理结构的搭建。MuJoCo 机器人模型、基础控制器、平面步态、墙面运动和地面至墙面切换仍属于后续研发内容。因此，现阶段成果应表述为“研发与协作基础已经建立”，而不是“机器人仿真已经完成”。

## 一 项目研究目标

本项目拟设计并仿真一款水下六足机器人，机器人具有以下结构特征：

- 机器人采用六足结构；
- 中央 `base_link` 为可折叠平台；
- 六个足端配置磁吸或黏附单元；
- 足端黏附单元开启后，可将机器人固定在接触面上；
- 机器人需要在水平面和竖直墙面上运动；
- 仿真环境采用 MuJoCo，当前阶段不接入 ROS。

项目研究任务分为三个层次：

1. 实现六足机器人在平面上的稳定站立、行走和机身位姿控制；
2. 实现机器人在墙面附着状态下的位姿保持和爬行控制；
3. 实现机器人由平面向墙面的自动切换，并提取可导入实体机器人控制器的流程参数。

第三项是项目的主要难点。预期切换流程为：机器人靠近墙面，前肢与墙面接触并开启黏附，确认前肢固定后折叠中央平台，使后肢靠近墙面；后肢接触并完成黏附后，平台恢复到墙面爬行姿态，最终进入墙面控制状态。

## 二 仓库在项目中的作用

本仓库既保存代码和模型，也作为智能院与机电院之间的技术协作载体。它主要解决以下问题：

- 统一机器人坐标系、单位、关节名称和足端名称；
- 明确机械模型与控制程序之间的数据接口；
- 记录任务负责人、交付物、截止时间和验收状态；
- 保存关键技术决策和会议结论；
- 管理仿真模型、控制参数、测试程序和实验结果；
- 为导师提供可追踪、可复现的阶段成果。

仓库地址：<https://github.com/Jx1nr2/underwater-hexapod>

## 四 根目录文件

### README

`README.md` 是仓库首页，概括项目背景、机器人结构、研究任务、目录布局和启动顺序。导师首次审阅仓库时，建议先阅读该文件。

当项目范围、运行方式或阶段成果发生变化时，应同步更新 README，避免首页信息与实际文件不一致。

### PROJECT BOARD

`PROJECT_BOARD.md` 是项目任务看板，用于记录：

- 任务编号和任务内容；
- 负责团队与具体负责人；
- 前置输入和预期交付物；
- 验收人和验收方法；
- 当前状态与阻塞原因。

该文件把口头安排转化为可追踪任务，是杭州与盐城两地团队进行异地协作的主要管理入口。

### GITIGNORE

`.gitignore` 用于排除不应提交到仓库的内容，例如 Python 缓存、编辑器临时文件、Word 锁定文件、运行日志和大型仿真输出。它不会删除本地文件，只会避免无关文件进入 Git 版本历史。

## 五 机械资源与 MuJoCo 模型

### assets meshes

`assets/meshes/` 计划保存机器人机身、腿部连杆、足端黏附单元和折叠平台等零件的三维网格。提交网格时需要同时说明：

- 文件单位与缩放比例；
- 零件坐标原点和方向；
- 网格对应的结构版本；
- 视觉网格与碰撞网格是否分离；
- 是否经过简化和尺寸校验。

### models

`models/` 计划保存 MuJoCo 的 XML 或 MJCF 模型，包括：

- 六足机器人本体模型；
- 平面站立和行走场景；
- 墙面附着和爬行场景；
- 地面至墙面的切换场景；
- 可复用的执行器、传感器和接触配置。

模型应遵守 `config/model_contract.yaml` 中约定的名称、单位和坐标系，使不同控制器能够在同一模型接口上运行。

当前 `assets/meshes/` 和 `models/` 中的 `.gitkeep` 只是空目录占位文件，不代表三维网格或 MuJoCo 模型已经完成。

## 六 config 机械与控制接口

### model contract

`config/model_contract.yaml` 是机械团队和控制团队共同遵守的模型接口合同。该文件以程序可读取的形式记录：

- 长度、角度、质量、力和力矩单位；
- `base_link` 与世界坐标系方向；
- 六条腿的编号和关节顺序；
- 各关节的类型、轴、零位、范围、速度和力矩限制；
- 可折叠平台的关节、方向和动作范围；
- 足端黏附的保持力、延迟、允许间隙和失效条件；
- 机器人质量、质心、惯量和浮力中心；
- 机械字段与控制字段的维护责任。

机电团队负责提供可信的机械参数，智能团队负责根据相同字段建立 MuJoCo 模型和控制器。涉及坐标系、关节名称或单位的修改，应由两院共同确认。

### control sequence template

`config/control_sequence_template.yaml` 是地面至墙面切换的控制序列模板。每个状态需要定义：

- 进入条件；
- 目标机身位姿；
- 目标关节位置；
- 足端黏附指令；
- 折叠平台目标；
- 完成判断条件；
- 超时时间；
- 失败后的回退状态。

推荐的最小状态流程如下：

```mermaid
flowchart LR
    A[靠近墙面] --> B[前肢接触]
    B --> C[前肢黏附确认]
    C --> D[平台折叠]
    D --> E[后肢靠近墙面]
    E --> F[后肢黏附确认]
    F --> G[平台恢复]
    G --> H[进入墙面控制]
```

仿真成功后，应导出时间戳、关节位置与速度、黏附指令、平台指令和硬件关节映射，使控制流程能够进一步转换为实体机器人输入。

## 八 控制程序 测试与实验记录

### src controllers

`src/controllers/` 计划保存 Python 控制程序，建议逐步实现：

1. 单关节位置控制；
2. 默认站立姿态控制；
3. 六足平面步态；
4. 机身高度、横滚、俯仰和偏航控制；
5. 足端黏附指令与状态确认；
6. 墙面位姿与步态控制；
7. 折叠平台控制；
8. 地面至墙面切换状态机；
9. 控制参数导入、记录和导出。

控制器应从 `config/` 读取关键参数，避免将接口名称和实验参数分散写死在代码中。

### tests

`tests/` 计划用于检查：

- MuJoCo 模型能否无错误加载；
- 六条腿、关节、执行器和传感器是否齐全；
- 模型名称是否与接口合同一致；
- 配置文件是否缺少关键参数；
- 关节目标是否超过安全范围；
- 足端接触与黏附状态是否可观测。

### runs

`runs/` 用于保存可复现实验记录。每次重要仿真应记录：

- Git 提交号；
- MuJoCo 与 Python 版本；
- 使用的模型和配置；
- 启动命令和随机种子；
- 机身位姿、关节状态和控制量；
- 足端接触力、黏附状态和滑移量；
- 实验截图、演示视频和结果结论；
- 已知限制与失败原因。

大型视频、CAD 和原始实验数据可以存放在学校网盘，但仓库中必须保留文件版本、哈希值、单位、下载地址和说明。不得上传网盘账号、密码或访问令牌。

## 十 研究阶段与验收目标

### M0 接口冻结

- 机械参数字段均有负责人和截止日期；
- 双方确认坐标系、零位、关节正方向和折叠方向；
- 网格单位与尺寸经过检查；
- 关键接口修改经过两院确认。

### M1 模型可视化与基础控制

- MuJoCo 能无报错加载机器人和地面场景；
- 关节数量、名称和范围与模型合同一致；
- 可以通过配置文件设置关节目标；
- 默认站立状态保持稳定；
- 仿真能够记录机身位姿、关节状态、控制量和接触状态。

### M2 平面步态与位姿控制

- 机器人能够在指定平面上稳定前进；
- 能够跟踪机身高度和姿态目标；
- 记录姿态误差、速度误差、足端滑移和控制峰值；
- 步态参数可以通过配置文件调整。

### M3 墙面附着与运动

- 六个足端的黏附状态可以独立控制和观测；
- 只有确认黏附成功的足端才能进入支撑集合；
- 机器人能够在竖直墙面保持姿态并完成步态周期；
- 对接触丢失、黏附不足和指令超时具有明确处理方式。

### M4 地面至墙面切换

- 完整切换流程由状态机自动执行；
- 各阶段目标、阈值、超时和回退参数均可配置；
- 能够统计成功率、最大姿态误差、足端滑移和总耗时；
- 控制序列可以回放和导出；
- 保留向实体机器人控制器映射的字段。

## 十一 导师和科研人员建议阅读顺序

1. 阅读本文件，了解研究目标与仓库整体分区；
2. 阅读 `README.md`，确认仓库入口和当前状态；
3. 阅读 `docs/01_project_charter.md`，审阅项目范围和两院分工；
4. 对照 `docs/02_interface_contract.md` 与 `config/model_contract.yaml`，检查机械控制接口；
5. 阅读 `docs/03_milestones_acceptance.md`，确认阶段验收指标；
6. 查看 `PROJECT_BOARD.md`，确认负责人、阻塞项和下一步交付；
7. 在出现关键技术路线变化时，查看 `docs/decisions/` 中的决策记录。

导师现阶段可重点确认以下问题：

- 第一阶段是否以 MuJoCo 模型可视化和基础控制为验收目标；
- 机电团队与智能团队的任务划分是否合理；
- 坐标系、关节命名、单位和接口字段是否完整；
- 足端优先采用磁吸、黏附还是可替换方案；
- 机械参数由谁提供，以及交付时间；
- 两地是否建立固定技术对接和教师决策机制。
