# 机械—控制接口协议

这份协议是两地团队的共同“真相源”。机械模型不能靠截图猜，控制算法也不能依赖未记录的临时参数。

## 坐标系

- 采用右手系。
- `base_link`：机器人展开且水平时，`+X` 指向前方，`+Y` 指向左侧，`+Z` 指向上方。
- 所有关节轴均在父链接坐标系中描述。
- 角度单位统一为 rad，长度为 m，质量为 kg，力为 N，力矩为 N·m。
- 墙面场景的法向由环境配置显式给出，不用“朝墙方向”之类的隐式描述。

## 命名规则

- 六条腿：`lf`、`lm`、`lr`、`rf`、`rm`、`rr`，分别表示左前、左中、左后、右前、右中、右后。
- 每条腿的关节按从机身到末端编号：`<leg>_j1`、`<leg>_j2`、`<leg>_j3`。
- 足端 site：`<leg>_foot_site`。
- 粘附执行器：`<leg>_adhesion`。
- 折叠平台关节：`base_fold_left`、`base_fold_right`；若机械方案不同，必须通过决策记录修改。

## 机电院必须交付的模型信息

| 类别 | 必填信息 | 格式 |
|---|---|---|
| 几何 | 各 link 尺寸、装配原点、网格缩放 | YAML + STL/OBJ |
| 动力学 | 质量、质心、惯量矩阵 | YAML |
| 关节 | 类型、轴、零位、上下限、最大速度/力矩 | YAML |
| 折叠平台 | 转轴、范围、锁止方式、动作时间 | YAML |
| 足端 | 接触面尺寸、材料、允许载荷 | YAML |
| 吸附 | 开关延迟、保持力、切向/法向上限、失效条件 | YAML + 实验记录 |

## 智能院必须交付的控制信息

| 类别 | 必填信息 | 格式 |
|---|---|---|
| 控制器 | 类型、频率、增益、限幅 | YAML + Python |
| 姿态 | 目标 base 位姿与容差 | YAML |
| 步态 | 相位、支撑腿集合、摆动轨迹 | YAML |
| 吸附时序 | 命令、确认条件、超时与失败处理 | YAML |
| 折叠时序 | 目标角、速度、同步条件 | YAML |
| 实验结果 | 版本、随机种子、日志与指标 | CSV/JSON |

## 粘附接口

控制器发出的不是“假定已吸住”，而是 `adhesion_command`；状态机只有收到 `contact_valid && adhesion_confirmed` 后才能把该足端计入支撑集合。仿真初期可用约束或等效力实现，但必须记录：

- 最大法向保持力；
- 最大切向保持力；
- 吸附建立和释放延迟；
- 足端与表面的允许距离和夹角；
- 超限后的失效行为。

## 平面—墙面切换状态机

建议最小状态如下：

```text
APPROACH_WALL
  -> FRONT_CONTACT
  -> FRONT_ADHESION_CONFIRM
  -> BASE_FOLD
  -> REAR_APPROACH
  -> REAR_CONTACT
  -> REAR_ADHESION_CONFIRM
  -> BASE_UNFOLD
  -> WALL_READY
```

每个状态必须包含进入条件、目标关节值、吸附命令、结束条件、超时、失败回退状态。参数保存在 `config/control_sequence_template.yaml`，之后可直接转换为硬件控制器的输入。
